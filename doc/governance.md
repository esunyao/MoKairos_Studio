# 文档分层与审计交接规范

本仓库参考 `UICRM-Embedded` 建立**总-分多级递推文档体系**，确保人类维护者与后续 AI 会话均能按需快速定位上下文，而不必猜测或重读全仓。

## 1. 文档层级职责

| 层级 | 位置 | 定位 | 维护规则 |
| :--- | :--- | :--- | :--- |
| **L0 根规范** | `AGENTS.md` / `README.md` | AI 协作硬规则与仓库门面 | `AGENTS.md` 首节「项目总体阅读说明」逐字不动 |
| **L1 全局文档** | `doc/` | 人类理解层：`README.md` 为总纲，专题拆至独立 `.md` | 文件名小写英文单数，不堆细节 |
| **L2 模块文档** | `src/doc/`、`src-tauri/doc/` + 各 `AGENTS.md` | 模块总览、分文件细则与「任务 → 读什么」导航 | 随接口/结构变更同步更新 |
| **本地私有层** | `doc-project/`、`**/docp/`（不提交） | 背景、视觉设计稿、阶段规划与审计总台账 | AI 绝不写入 `**/docp/`；规划与审计登记在 `doc-project/` |

## 2. 任务审计与交接闭环

每次完成功能开发或重构任务，均须在 `doc-project/audit/` 同步记录：
1. 在 [审计总台账](../doc-project/audit/README.md) 登记「日期、任务名称、关联提交、状态、报告链接」；
2. 新建 `doc-project/audit/YYYYMMDD-<task>-audit.md`，记录改动对照、自动化测试/构建量化证据、界面实测 Walkthrough、外部仓库零改动核验及未验证项。
